# PersonLLMWiki 打包与发布

> 本文合并自原「分发部署方案」与「开发者打包发布指南」，覆盖 **zip + Embedded Python** 分发形态的设计与操作全流程。
> 桌面安装版（PyWebView + PyInstaller + Inno Setup）见 [PyWebView桌面窗口壳设计方案](../02-设计/06-PyWebView桌面窗口壳设计方案.md)；安装版升级见 [§14](#14-安装版自动升级f82026-08-24)。

## 1. 分发形态与选型

两种分发形态并存：

| 形态 | 分发物 | 目标用户 | 文档 |
|---|---|---|---|
| zip + Embedded Python | `PersonLLMWiki-v<版本>.zip` | 开发者 / 内测 | 本文 |
| 桌面安装包 | `PersonLLMWiki-Setup-<版本>.exe` | 最终非技术用户 | [PyWebView桌面窗口壳设计方案](../02-设计/06-PyWebView桌面窗口壳设计方案.md) |

### 1.1 为什么 Embedded Python

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **Embedded Python**（微软官方 embeddable zip） | 体积可控（~100MB）、官方维护、无需管理员权限 | 首次需引导 pip | ✅ 选定 |
| PyInstaller 单文件 | 单文件分发 | 编译复杂、体积 200MB+、MCP 二进制难打包 | ❌ |
| Docker | 环境隔离 | 普通用户装 Docker 更难 | ❌ |

### 1.2 依赖与数据目录

- 所有依赖（flask / openai / pymupdf / fastembed / fastmcp 等）在 Windows x64 均有预编译 wheel，无需 C 编译器，适合 Embedded Python。
- 数据目录 `resource/` 升级时**必须保留**，其余代码可覆盖。

## 2. 目标目录结构

```
PersonLLMWiki/                     ← 分发根目录（解压即得）
├── runtime/                       ← 内嵌 Python 运行时（~30MB）
├── app/                           ← 应用代码（升级时覆盖）
├── resource/                      ← 用户数据（升级时保留，永不覆盖）
├── 启动.bat / 停止.bat / 升级.bat  ← 用户侧脚本
├── .env                           ← 环境变量配置（可选）
└── VERSION                        ← 当前版本号
```

关键决策：`runtime/` 与 `app/` 分离（升级只覆盖 `app/`）、`resource/` 独立于 `app/`、`启动.bat` 内置环境自检（**启动即安装**，无需单独的首次安装.bat）。

## 3. 环境准备（开发者）

- Python 3.10+（开发机，仅用于跑打包脚本）；分发包内嵌 Python 3.12.8 Embedded。
- 打包相关代码在 `packaging/`：`fetch_runtime.py`（运行时下载与引导）、`build_release.py`（打包编排）、`scripts/*.bat`（用户侧脚本）、`versions.json.template`（版本清单模板）。

## 4. 打包

### 4.1 全量包（首次发布）

```bash
python packaging/build_release.py 1.0.0
```

流程：下载 Embedded Python（已缓存则跳过）→ 启用 site-packages（取消 `._pth` 的 `import site` 注释）→ 引导 pip → 装 `requirements.txt` 依赖 → 复制 `app/` 代码 → 复制 bat 脚本 + `.env` + VERSION → 打 zip。产物 `packaging/dist/PersonLLMWiki-1.0.0.zip`。

### 4.2 增量包（版本升级）

```bash
python packaging/build_release.py 1.1.0 --update
```

仅复制 `app/` 代码 → `PersonLLMWiki-1.1.0-update.zip`。

> 何时用增量：runtime 无大版本变化、依赖无重大变更时一律增量；仅 Python 大版本升级或引入不兼容 native 依赖时才重发全量包。

## 5. 安装与启动

### 5.1 首次使用

解压 → 双击 `启动.bat`（内置环境自检，缺失自动修复）→ 浏览器自动打开 http://127.0.0.1:5000。

### 5.2 启动 / 停止

- 启动：双击桌面快捷方式或 `启动.bat`（端口已占用时自动打开已运行实例，不重复启动）。
- 停止：关闭命令行窗口，或双击 `停止.bat`（按端口清理进程）。

### 5.3 用户体验流程

| 阶段 | 步骤 |
|---|---|
| 首次 | 解压 → 双击启动 → 开始使用 |
| 日常 | 双击桌面图标 → 浏览器打开 → 用完关闭 |
| 升级 | 双击 `升级.bat` → 自动检测/下载/应用（约 30 秒） |

## 6. 升级

### 6.1 升级策略

**下载 zip 覆盖**（不依赖 git）：`升级.bat` 调 `common/upgrade_check.py` 的 `check → download → apply` 三子命令。

### 6.2 版本清单 versions.json

```json
{
  "latest": "1.2.0",
  "versions": {
    "1.2.0": {
      "url": "https://example.com/personllmwiki/PersonLLMWiki-1.2.0-update.zip",
      "date": "2026-08-06",
      "notes": "更新说明",
      "min_runtime": "1.0.0",
      "size_mb": 15
    }
  }
}
```

### 6.3 升级脚本

- `packaging/scripts/升级.bat`：停服务 → 查版本 → 下载增量包 → 备份 + 应用 → 更新依赖。
- `common/upgrade_check.py`：`check`（exit 0=有更新 / 2=已最新 / 1=错误）、`download`、`apply`（备份 `app/` → 覆盖 → 失败回滚）。

### 6.4 Web 端在线更新（设置页 → 关于页签）

`POST /api/settings/upgrade/check`（对比 versions.json）+ `POST /api/settings/upgrade/apply`（下载 + 备份 + 解压）。**开发模式（存在 .git）禁用在线更新**，提示用 `git pull`。

### 6.5 升级安全机制

| 保障 | 说明 |
|---|---|
| 备份回滚 | 升级失败自动恢复 `app_backup/` |
| 数据安全 | `resource/` 不参与升级，永不丢失 |
| 种子同步 | 升级后 `seed/skills/`、`seed/mcp/` 自动同步（新增→追加、变更→覆盖、用户自建→保留） |
| 依赖检测 | 升级后检测 `requirements.txt` hash，有变化才 pip install |
| 版本回滚 | 把 `versions.json` 的 `latest` 指回旧版即可降级（需保留历史 zip） |

> 安装版（Setup.exe）升级走 GitHub Releases，见 [§14](#14-安装版自动升级f82026-08-24)。

## 7. 发布

### 7.1 准备版本清单

更新 `versions.json`：`versions` 对象新增版本条目 + `latest` 指向最新。

### 7.2 上传与分发

| 方式 | 适用场景 |
|---|---|
| 直接传 zip | 内部团队、U 盘 |
| 网盘 | 小规模分发 |
| 内部 HTTP 服务器 | 配合 versions.json 实现自动升级 |
| GitHub Releases | 开源项目（可配 Actions 自动化） |

### 7.3 升级服务器搭建

Nginx / Apache 静态托管 `versions.json` + zip 包即可（无后端逻辑）。`versions.json` 的 URL 必须固定（`升级.bat` 硬编码 `VERSIONS_URL`）。

## 8. 版本管理规范

语义化版本 `MAJOR.MINOR.PATCH`：MAJOR 不兼容改（数据库结构/API 大改）、MINOR 新增功能、PATCH 修复。

升级兼容性：增量包只更新 `app/`；数据库 `app.py` 自动迁移；`resource/` 保留；`seed/` 覆盖；`runtime/` 仅大版本升级时更新（重发全量包）。

## 9. 配置（.env / config.py）

`.env` 可配：`RESOURCE_BASE_PATH`（数据目录）、`PORT`（默认 5000）、`INSTANCE_MODE`（single/personal/public）、`COMMON_GIT_REPO`、LLM 配置等。`config.py` 从 `.env` 读取；`app.py` 端口从 `PORT` 环境变量读取。

## 10. 测试验证

1. 解压全量包到干净目录 → 首次安装无报错；
2. 启动 → 浏览器正常打开、各模块可用；
3. 生成增量包模拟升级 → 升级后数据完整、版本号更新。

常见问题：pip 引导失败（网络）、依赖无 wheel（检查 win_amd64）、体积过大（fastembed/onnxruntime 可选拆分）、`.env` 被打包（确认在排除列表）、升级后启动失败（回滚 + 改发全量包）。

## 11. CI/CD 集成（GitHub Actions）

打 tag 触发：build 全量包 + 增量包 → upload-artifact（可选追加 `action-gh-release` 发布到 Releases）。

## 12. 错误处理与日志

日志重定向到 `logs/`；常见错误：端口占用（启动.bat 预检）、runtime 损坏（重引导）、数据库锁（确保单实例）、依赖缺失（自动 pip）、防火墙（监听 127.0.0.1 不触发）。

## 13. 后续迭代

桌面窗口壳（已实现）、开机自启、macOS 支持、自动更新检查（托盘气泡）、数据备份导出、多用户网络部署（gunicorn + Nginx）。

## 附录：快速参考

```bash
python packaging/build_release.py 1.0.0                # 全量打包（首次发布）
python packaging/build_release.py 1.1.0 --update       # 增量打包（版本升级）
python packaging/fetch_runtime.py ./test_runtime requirements.txt  # 单独构建 runtime
```

## 14. 安装版自动升级（F8，2026-08-24）

> 本节为原「安装版自动升级设计方案」并入。目标：安装版（Setup.exe / PyInstaller EXE）用户可**自动检测新版本并下载升级**，避免"推广开后逐个手动发安装包"。
> 机制：检测走 **GitHub Releases API**，升级走**下载新版 Setup.exe 并引导安装**（含 UAC 提权）。
> 现状差异：现有在线升级（`/api/settings/upgrade/*` + versions.json + zip 覆盖）只适用于**源码/zip 部署**；安装版代码封在 EXE（PYZ）+ `_internal`，zip 无法原地覆盖 → 需独立的安装版通道。

### 14.1 版本标识（前置修正）

| 现状 | 问题 | 修正 |
|---|---|---|
| `VERSION`（根）= `1.0.1`；完整构建号 `1.0.1.006` 只在安装包名 | 应用 `_get_current_version()` 读 VERSION 返回 `1.0.1`，无法与 `1.0.1.007` 比较 | **构建时生成 `app_version.txt`（含完整版本）并打进包**（datas → `_internal/app_version.txt`）；`_get_current_version()` 优先读它（`sys.frozen` 时），否则回退 VERSION |
| `_is_embedded_mode()` 按 `'runtime' in sys.executable` | 对安装版 EXE（`D:\PersonLLMWiki\PersonLLMWiki.exe`）**不生效** | 安装版判定改用 **`getattr(sys, 'frozen', False)`** |
| `_compare_versions` 为 3 段比较 | 需要 4 段（1.0.1.007） | 支持 4 段（缺段补 0） |

### 14.2 更新检测（GitHub Releases）

- 新 helper `_check_github_release()`：`GET https://api.github.com/repos/zsafly-star/PersonLLMWiki/releases/latest`（UA `PersonLLMWiki-Updater`，超时 15s），解析：
  - `tag_name` → 版本（兼容 `v` 前缀，如 `v1.0.1.007`）
  - `name` / `body` → 更新说明（取前 N 行）
  - `published_at` → 日期
  - `assets[]` → 匹配 `PersonLLMWiki-Setup-*.exe` 的 `browser_download_url` 与 `size`
- 版本比对（4 段）→ `has_update`。
- **发版约定**：GitHub **tag 必须用完整构建号**（`v1.0.1.007`），release 附件必须含 `PersonLLMWiki-Setup-<完整版>.exe`——否则检测不到（tag 用 `1.0.1` 会导致 `1.0.1.007 > 1.0.1` 永远成立/或误判，**本次发版起统一完整 tag**）。

### 14.3 下载并升级

- 新接口 `/api/settings/upgrade/download-setup`：从 `browser_download_url` 下载 Setup.exe 到临时目录（`%TEMP%`），返回本地路径与大小。
- 新接口 `/api/settings/upgrade/launch-installer`（POST，body 带本地路径）：
  1. 正常退出应用（桌面壳：复用 `_allow_close=True` + `PostMessageW(WM_CLOSE)` 走托盘退出；源码/Web 模式：直接结束进程兜底）；
  2. 退出后 `subprocess.Popen([setup_path], cwd=tmpdir, creationflags=CREATE_NO_WINDOW)` 启动安装器——安装器 manifest `requireAdministrator` → **Windows 自动弹 UAC**，用户确认后进入安装向导（默认目录 `{pf}\PersonLLMWiki`，覆盖安装）。
  3. 用户数据在 `~/.personllmwiki`，安装覆盖不影响。
- 前端（settings.html 版本与更新区）：
  - 安装版（`can_online_update` + `sys.frozen` 语义）检测结果展示：`发现新版本 x.y.z（大小）` + 更新说明 + **「下载并升级」**按钮；
  - 点击 → 确认弹窗「将退出应用并启动安装向导，是否继续？」→ 下载进度态 → 调 `launch-installer`。

### 14.4 接口分流（不破坏现有源码版升级）

`/api/settings/upgrade/check` 按运行模式分流：
- `sys.frozen`（安装版）→ GitHub Releases 检测，返回结构兼容现有字段（`latest/current/has_update/notes/date/size_mb/url`）+ `kind: 'installer'`；
- 非 frozen（源码/zip 部署）→ 维持现有 versions.json 流程（`kind: 'zip'`），前端按 kind 显示「下载并升级」（installer）或「在线更新」（zip）。

### 14.5 风险与限制

- **SmartScreen**：安装包未代码签名，下载后首次运行可能提示「未知发布者」——用户需点「仍要运行」（现状限制，README 注明）。
- **GitHub API 限流**：未认证 60 次/时/IP，客户端低频检查（启动后一次 + 手动）无压力。
- **UAC**：admin 安装器必然弹一次 UAC（无法绕过，属 Windows 安全机制）。
- **全自动静默升级**（下载→自退出→`/VERYSILENT`→自动重启）列为后续迭代；本次先做「检测 + 下载 + 引导安装」。

### 14.6 实施清单（Trae）

1. `packaging/build_desktop.py`：构建时生成 `app_version.txt`（`<完整版本>`）→ 加入 `desktop.spec` datas（`_internal/`）。
2. `src/modules/settings/routes.py`：
   - `_get_current_version()`：frozen 时优先读 `app_version.txt`；`_compare_versions` 支持 4 段；
   - 新增 `_check_github_release()` 与 `/api/settings/upgrade/download-setup`、`/api/settings/upgrade/launch-installer`；
   - `/api/settings/upgrade/check` 按 `sys.frozen` 分流（installer/zip），返回 `kind` 字段。
3. `src/modules/settings/templates/settings.html`：版本与更新区按 `kind` 渲染；安装版显示「下载并升级」按钮 + 确认弹窗 + 下载/启动流程。
4. `src/desktop.pyw`：提供可复用的退出入口（`_quit_app` 已有，供 launch-installer 复用）。
5. 文档：本方案落地后同步任务书 §7 F8、README（更新方式章节）。

### 14.7 验证路径

1. 源码模式回归：现有 versions.json 升级流程不受影响（kind='zip' 分支）。
2. 安装版（.007+）：设置页「检查更新」→ 无更新时显示当前版本；有更新时显示新版本+说明+按钮；下载 Setup.exe 成功；点升级 → 应用退出 → UAC → 安装向导出现。
3. 版本比对：4 段（1.0.1.007 vs 1.0.1.006）；tag 带/不带 `v` 前缀均兼容。
