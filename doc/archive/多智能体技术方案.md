## 0. 相对 PRD 的决策变更

| 议题 | PRD 原方案 | 最终决策 | 变更原因 |
| ---- | ---------- | -------- | -------- |
| 智能体数量 | 主管-工作者多智能体 | **单 agent 分阶段角色** | 单人工具 + 流程偏线性，无需多 agent 协调 |
| 编排引擎 | LangGraph（倾向引入） | **不引入，手写编排** | 线性流水线 + 闸门，for 循环 + 状态表足够 |
| 流程定义形式 | 注册流程定义（形式未定） | **数据库存储 + 界面管理** | 步骤需可视化增删改 |
| 顶层分发 | Router（概念已有） | **router + skills 场景分发** | 多场景可枚举，路由分发最契合 |
| 安全 | 五层 + 两轴判定 | **白名单 + 写/导出二次确认** | 单人自用，简化够用 |

## 1. 总体架构

```
用户输入
  ↓
L1 Router（场景意图分发）───────────────────────── 轻量 LLM 分类
  ↓
场景流程定义（数据库 Scenario + ScenarioNode）────── 控制台"智能体"标签界面管理
  ↓
L2 编排器（单 agent 分阶段执行）────────────────── 手写 for 循环 + 闸门
  ├─ 节点1(需求) → [人工闸门] → 节点2(原型) → [闸门] → ...
  └─ 每个节点 = 同一个 react loop，只换角色 prompt + 工具白名单
  ↓
L3 能力执行（react loop + MCP 工具）──────────────── 复用现有 common/agent.py
  ↓
L4 状态持久化（TaskState 表）────────────────────── 命脉：断点续跑 + 上下文重建
  ↓
L5 产物落盘（文件 / 知识库 / 导出文档）
```

**核心思想**：单 agent 跑多步骤 = 同一 react loop 分阶段换角色，而非多个独立智能体。顶层用 router 把多场景接起来，每个场景内部是一段线性流水线。

### 3.2 ScenarioNode（步骤 / 节点）

```python
class ScenarioNode(db.Model):
    __tablename__ = 'scenario_node'
```

## 4. 流程定义与界面管理

### 4.1 设计原则

步骤**数据驱动、界面可编辑**，不写死在代码里。场景 = 数据库记录，节点 = 场景下的有序子记录。用户可随时增删节点、调整顺序、修改角色提示词、开关闸门、调整工具白名单，**无需改代码、无需重启**。

### 4.2 控制台「智能体」标签 UI

```
┌──────────────────────────────────────────────────┐
│ [自动化] [MCP] [Skill] [智能体]                    │
├───────────────┬──────────────────────────────────┤
│ 场景列表       │ 选中场景的节点流水线               │
│ ─────────     │ ─────────                        │
│ ● 写代码       │ [1] 需求   gate:✓  白名单:…  [编辑]│
│ ○ 写 PPT       │ [2] 原型   gate:✓  白名单:…  [编辑]│
│ ○ 导入待办     │ [3] 开发   gate:✓  白名单:…  [编辑]│
│ ○ 年度总结     │       [+ 添加节点]                │
│ [+ 新建场景]   │                                   │
└───────────────┴──────────────────────────────────┘
```

- 节点可拖拽排序、增删、编辑（名称 / 角色提示词 / 闸门开关 / 工具白名单多选）。
- 内置场景（写代码 / 写 PPT / 导入待办）首次启动由 seed 插入数据库，之后用户可自由修改，不被覆盖。

## 6. 编排器（单 agent 分阶段执行）

核心：`for node in plan: run_agent_loop(role_prompt=node, allowed_tools=node)`，节点完成 → 闸门 → 挂起/继续。

```python
def run_task(task_id):
    task = state_store.load(task_id)
    nodes = state_store.load_plan(task)          # 发起任务时从场景定义固化的节点序列

    for node in nodes:
        if task.state == 'paused':               # 用户暂停
            return

        task.state = 'running'
        task.current_node = node.key
        state_store.save(task)

        # ── 单 agent 分阶段：同一 react loop，换角色 + 白名单 ──
        result = run_agent_loop(
            messages=state_store.build_messages(task),   # 用 resume_context 重建
            role_prompt=node.role_prompt,
            allowed_tools=node.allowed_tools,
            progress_callback=...,
        )

        state_store.save_artifact(task, node.key, result)

        # ── 人工闸门 ──
        if node.gate:
            task.state = 'awaiting_user'
            task.pending_approval = {
                'node': node.key,
                'question': f'请确认「{node.name}」的产出',
                'ai_recommended_plan': ...,
            }
            state_store.save(task)
            return                              # 挂起，等用户确认

    task.state = 'done'
    state_store.save(task)
```

**执行方式**：长时任务用后台线程（复用 automation 的 `threading.Thread + app.app_context()` 模式），避免阻塞请求。

## 7. 上下文重建与断点续跑（核心风险点）

断点续跑最难的**不是存状态，而是恢复时如何重建 LLM 上下文**。方案：不塞回整段对话，只存"精简摘要 + 指针"。

`resume_context` 结构：

```json
{
  "current_node": "develop",
  "goal": "为 PersonLLMWiki 增加 TODO 入口",
  "confirmed_artifacts": [
    {"node": "requirement", "summary": "需求：新增 TODO 看板，含增删改查…", "path": "note://req-001"},
    {"node": "prototype", "summary": "原型：三列看板 + 优先级标签…", "path": "note://proto-001"}
  ],
  "next_step": "基于已确认需求与原型，编写后端路由与前端页面"
}
```

恢复流程：

1. 用户点"继续" → 读 `TaskState`，取出 `resume_context`。
2. 用 `goal + confirmed_artifacts + next_step` 拼成一条精简的 system/user 消息，**不携带历史工具调用细节**。
3. 从 `current_node` 继续执行 `run_agent_loop`。

要点：`artifacts` 存**产物指针**（note/path），不存原文；`resume_context` 存**摘要**，不存完整对话。敏感产物只留指针，契合 PRD 安全要求。

## 9. 安全（简化版）

沿用 PRD 的"白名单 + 二次确认"核心，简化掉两轴判定的完整分级实现。

| 措施 | 落地位置 | 说明 |
| ---- | -------- | ---- |
| 节点工具白名单 | `ScenarioNode.allowed_tools` | 每节点只递送最小工具集，用完即回收 |
| 工具参数校验 | `security.py` | 路径越界校验（禁止写项目根之外） |
| 写/导出二次确认 | `security.py` + 闸门 | 写文件、导出文档前强制确认 |
| 越权直接拦截 | `security.py` | 白名单外的工具调用直接拒绝，不进入确认 |
| 敏感数据只留指针 | `TaskState.artifacts` | 不落原文，只存 note/path |

> 完整的两轴判定（L1-L4 数据分级 × 动作风险）留待后续需要 L4 隐私/合同数据时再补全，架构上已预留 `allowed_resources` 扩展位。
