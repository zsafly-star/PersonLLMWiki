
# 阶段节点式思考过程组件 开发规格说明（v2.0）

本文档为可被AI直接理解并执行开发的精确规格，包含**数据协议、渲染逻辑、状态流转、交互规则**四大核心模块，所有定义均为强约束，开发输出需严格匹配以下规范。

> **v2.0 变更摘要**：新增专家模式强制流程（知识库→联网→整理思路）、`custom_stage` 非工具阶段、"生成回答"收尾阶段、历史消息恢复思考过程、工具调用轮次标注。

## 一、组件核心定义

组件全称：阶段节点式推理思考可视化组件
核心能力：将AI完整思考链路拆分为离散的逻辑阶段节点，以横向进度节点形式展示推理进度；用户可点击节点展开对应阶段的详细思考内容；思考区域与最终答案区域物理隔离，支持流式增量更新与用户中途介入。
适用输入：后端 SSE 事件流（实时）/ `thinking_json` 持久化数据（历史）；适用输出：可交互的DOM组件（Web/H5/PC端通用）。

## 二、阶段模型与触发机制

思考过程的阶段来源分为三类，由后端统一编排推送：

### 2.1 固定阶段

| 阶段 | 触发条件 | 说明 |
|------|----------|------|
| 分析问题 | 所有模式，始终为第1阶段 | LLM 思考期间显示 |

### 2.2 工具阶段（tool_start / tool_result）

LLM 自主调用工具时动态产生。每次 `tool_start` → 新增一个节点，`tool_result` → 标记完成。

工具名中文映射表 `TOOL_CN_MAP`：

```python
TOOL_CN_MAP = {
    'search_kb': '搜索知识库', 'read_note': '读取笔记',
    'read_wiki_page': '读取Wiki', 'write_note': '保存笔记',
    'list_folders': '列出目录', 'compile_wiki': '编译Wiki',
    'create_document': '创建文档', 'add_element': '写入内容',
    'get_structure': '获取结构', 'get_outline': '获取大纲',
    'set_element': '设置元素', 'read_document': '读取文档',
    'read_sheet': '读取表格', 'write_cells': '写入数据',
    'list_sheets': '获取表格', 'approve_candidate': '审批内容',
    'query_materials_by_params': '查询物料', 'get_material': '物料详情',
    'create_folder': '创建目录',
    'websearch__web_search': '联网搜索',
}
```

轮次标注：当 `round > 1` 时，阶段名追加"(第N轮)"，如"搜索知识库(第2轮)"。

### 2.3 自定义阶段（custom_stage_start / custom_stage_end）

非工具的展示性阶段，用于标记 Agent 内部流程节点。当前使用：

| 阶段 | 触发条件 | 说明 |
|------|----------|------|
| 整理思路 | 专家模式强制流程第3步 | 搜索完成后、生成回答前 |
| 生成回答 | 所有模式，thinking_done 前 | 标记进入最终回答生成阶段 |

### 2.4 各模式的阶段流转

**专家模式**（强制流程，5+N 阶段）：
```
分析问题 → 搜索知识库(自动) → 联网搜索(自动) → 整理思路 → [LLM工具调用...] → 生成回答
```
- 第2-3步为系统自动注入：`search_kb` + `websearch__web_search`，结果注入 LLM 上下文
- LLM 可在此基础上继续调用其他工具

**快速模式**（LLM 自主，2+N 阶段）：
```
分析问题 → [LLM工具调用...] → 生成回答
```

## 三、输入数据协议

### 3.1 SSE 事件协议（实时流）

后端通过 SSE 逐事件推送，前端增量渲染。事件类型如下：

| 事件 | 触发时机 | data 字段 |
|------|----------|-----------|
| `stage_start` | 固定/工具/自定义阶段启动 | `{stage_id, stage_name, tool_name?, tool_arguments?, round?, status, start_timestamp}` |
| `stage_end` | 工具/自定义阶段结束 | `{stage_id, status, end_timestamp, content?}` |
| `heartbeat` | 队列2秒超时且线程存活 | `{heartbeat: true}` |
| `thinking_done` | 所有阶段完成 | `{thinking_done: true}` |
| `chunk` | 最终回复分块输出 | `{chunk: "文本片段"}` |
| `done` | 完全结束 | `{done: true, stopped: bool, thinking: payload}` |

`stage_start` 完整数据示例：

```json
{
  "stage_start": {
    "stage_id": "stage_2",
    "stage_name": "搜索知识库",
    "tool_name": "search_kb",
    "tool_arguments": {"keyword": "RESTful API"},
    "round": 1,
    "status": "processing",
    "start_timestamp": 1720000009
  }
}
```

自定义阶段（无工具）数据示例：

```json
{
  "stage_start": {
    "stage_id": "stage_5",
    "stage_name": "生成回答",
    "status": "processing",
    "start_timestamp": 1720000020
  }
}
```

### 3.2 持久化数据协议（thinking_json）

最终持久化到 `ChatMessage.thinking_json` 字段：

```json
{
  "stages": [
    {
      "stage_id": "stage_1",
      "stage_name": "分析问题",
      "status": "completed",
      "start_timestamp": 1720000001,
      "end_timestamp": 1720000008
    },
    {
      "stage_id": "stage_2",
      "stage_name": "搜索知识库",
      "tool_name": "search_kb",
      "tool_arguments": {"keyword": "RESTful API"},
      "round": 1,
      "status": "completed",
      "start_timestamp": 1720000009,
      "end_timestamp": 1720000012,
      "content": "搜索结果摘要..."
    }
  ],
  "exported_files": [
    {"filename": "分析报告.docx", "path": "/data/file_exports/分析报告.docx"}
  ]
}
```

### 3.3 字段强约束

1. **状态枚举值**：
   - 节点状态 `status`：仅允许 `pending`（待执行）、`processing`（进行中）、`completed`（已完成）、`error`（异常）四种
2. `stage_id` 为全局唯一标识，按思考顺序从1递增编号；`stage_name` 为不超过8个汉字的阶段名称
3. `tool_name` / `tool_arguments` / `round` / `content` 为可选字段，仅工具阶段携带
4. `exported_files` 从 `tool_name == 'create_document'` 的阶段中提取（按文件名去重）

## 四、DOM结构与布局规则

### 4.1 实时思考面板（流式输出中）

组件整体分为上中下三层，垂直排列：

```
[ 阶段节点进度栏 ]  高度固定，位于组件最顶部
[ 思考详情面板 ]    可折叠区域，位于进度栏下方，默认收起
[ 最终答案区域 ]    主体内容区，位于最底部，始终展示
```

### 4.2 历史消息思考面板（加载已完成消息）

历史消息中的思考过程以**可折叠摘要**形式展示在回答气泡上方：

```
[ 💡 思考过程 ▼ ]  ← 点击展开，默认收起
[ 回答正文 ]
```

展开后复用实时面板的节点进度栏样式，但：
- 无呼吸动画（所有节点已完成）
- 无跳过按钮
- 无详情面板（仅展示节点进度条）

### 4.3 各区域渲染规则

1. **阶段节点进度栏**
   - 内部横向排列所有阶段节点，节点数量 = 已推送的 stage 总数
   - 单个节点由「圆形状态图标 + 阶段名称文字」组成，节点之间用连接线串联
   - 节点水平居中均匀分布，响应式适配容器宽度；节点数量≥6时，自动缩小字号与图标尺寸
2. **思考详情面板**
   - 默认状态：全局收起，仅在用户点击节点时展开，展示对应阶段的 `content` 内容
   - 面板顶部显示「当前阶段：xxx」标题，右侧内置「收起」按钮
   - 内容超长时，面板最大高度限制为300px，超出部分纵向滚动
3. **最终答案区域**
   - 顶部有明确的「最终答案」分割标题，与思考区形成物理边界
   - 思考未完成时，区域显示占位提示「思考完成后将展示最终答案」；思考完成后流式输出正文

## 五、状态流转与更新逻辑

### 1. 节点状态视觉映射

| 节点状态   | 圆形图标样式              | 文字样式       | 连接线样式                     |
| :--------- | :------------------------ | :------------- | :----------------------------- |
| pending    | 灰色空心圆                | 浅灰色文字     | 灰色虚线                       |
| processing | 蓝色实心圆 + 呼吸动效     | 蓝色加粗文字   | 前半段蓝色实线，后半段灰色虚线 |
| completed  | 蓝色实心圆 + 白色对勾图标 | 深灰色常规文字 | 蓝色实线                       |
| error      | 红色实心圆 + 白色感叹号   | 红色文字       | 红色实线                       |

### 2. 流式更新规则

后端 SSE 逐事件推送时，前端按以下逻辑增量渲染：

1. 收到 `stage_start` 事件时：创建新节点，状态为 `processing`，进度栏自动高亮当前节点，标记前一节点为 `completed`
2. 收到 `stage_end` 事件时：将对应节点状态切换为 `completed`，记录结束时间
3. 收到 `thinking_done` 事件时：全局状态切换为 `completed`，自动收起详情面板
4. 收到 `chunk` 事件时：追加到最终答案区域，流式输出正文
5. 收到 `heartbeat` 事件时：忽略（仅维持连接）
6. 收到 `done` 事件时：持久化完成，携带最终 `thinking` payload

### 3. 全局状态流转路径

`初始化 → processing → （用户可触发 skipped） → completed / error`

- 触发「跳过思考」操作后，全局状态强制置为 `skipped`，所有未完成节点标记为 `completed`，立即渲染最终答案
- 任一节点出现 `error` 状态时，全局状态置为 `error`，终止后续思考输出，在详情面板展示错误提示

## 六、交互行为规范

所有交互行为为强制要求，不可省略。

1. **节点点击**：点击任意 `completed` 或 `processing` 状态的节点，展开详情面板并展示对应阶段内容；点击已选中的节点，收起面板。`pending` 状态节点不可点击，鼠标悬浮显示「待执行」提示。
2. **跳过思考按钮**：进度栏右侧固定显示「跳过思考」按钮，仅在 `global_status = processing` 时可点击；点击后立即终止思考展示，直接输出最终答案，按钮消失。
3. **自动滚动**：阶段切换时，进度栏自动横向滚动，保证当前进行中节点始终处于可视区域中央。
4. **内容复制**：详情面板右上角内置「复制本段」按钮，点击仅复制当前阶段的思考内容；支持全局右键复制。
5. **全局收起**：点击详情面板「收起」按钮，面板折叠，仅保留顶部进度栏。
6. **历史展开**（v2.0新增）：历史消息中的「思考过程」标题可点击展开/收起节点进度条，不影响回答正文。

## 七、边界与异常处理

1. 单阶段内容为空时，详情面板显示「本阶段无详细记录」
2. 思考数据加载失败时，进度栏整体置灰，显示「思考过程加载失败」，不影响最终答案展示
3. 阶段数量≤1时，自动降级为普通折叠式思考组件，隐藏节点进度条
4. 移动端窄屏（宽度<768px）下，阶段名称自动隐藏，仅保留圆形节点，悬浮/长按显示名称
5. 专家模式自动搜索失败时（知识库/联网），阶段仍标记为 `completed`，结果注入错误提示文本，不中断流程

## 八、专家模式强制流程（v2.0新增）

### 8.1 设计目标

专家模式下不再依赖 LLM 自主决定是否搜索，而是**系统强制执行**两路搜索，保证信息充分。

### 8.2 流程编排

```
用户提问
  │
  ├─ 1. 提取用户最新问题（取 messages 中最后一条 role=user 的 content）
  │
  ├─ 2. 自动调用 search_kb(keyword=用户问题)
  │     → 推送「搜索知识库」stage_start/stage_end
  │     → 结果存入 context_parts
  │
  ├─ 3. 自动调用 websearch__web_search(query=用户问题)
  │     → 推送「联网搜索」stage_start/stage_end
  │     → 结果存入 context_parts
  │
  ├─ 4. 推送「整理思路」custom_stage_start/end
  │
  ├─ 5. 将两路搜索结果注入 full_messages 作为 system 消息
  │
  └─ 6. 进入正常 agent_chat 循环（LLM 可继续调用工具或直接回答）
```

### 8.3 预搜索结果注入格式

```python
full_messages.append({
    'role': 'system',
    'content': '以下是针对用户问题的自动搜索结果，请综合这些信息来回答：\n\n'
               '【知识库搜索结果】\n...\n\n'
               '【联网搜索结果】\n...'
})
```

## 九、开发验收标准

1. 输入符合协议的JSON数据，可正确渲染对应数量、对应状态的节点
2. 模拟流式增量推送数据，节点状态、内容可无刷新实时更新
3. 所有交互操作响应延迟≤100ms，无页面卡顿
4. 思考过程与最终答案视觉边界清晰，无样式混淆
5. 触发「跳过思考」后，100ms内切换至最终答案展示状态
6. 专家模式下自动出现「搜索知识库→联网搜索→整理思路→生成回答」完整阶段链
7. 快速模式下至少出现「分析问题→生成回答」两个阶段，不直接跳到结果
8. 历史消息加载时，有思考过程的消息（stages.length > 1）显示可折叠的「思考过程」面板
