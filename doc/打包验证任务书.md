# 打包验证任务书（Packaging Verification Brief）

> 版本：v1.0（2026-08-22）｜ 类型：设计文档（可执行规范）
> **本文件可被任意 AI 编码工具直接执行**（Claude Code / Cursor / Trae / Codex / DeepSeek Harness 子 agent / CI），无需会话上下文。
> 适用环境：Windows（项目打包目标平台为 Windows x64），需 Python + PyInstaller + Inno Setup。

---

## 0. 目标

验证当前代码可成功打包、产物可用，输出结构化报告。**不改源码**，除非明确是环境/依赖问题。

## 1. 前置检查（每项记录结果）

| # | 检查 | 命令 | 预期 |
|---|---|---|---|
| 1.1 | 工作树状态 | `git status -s` | 记录未提交项（不阻断） |
| 1.2 | Python 可用 | `python --version` | ≥ 3.8 |
| 1.3 | PyInstaller | `python -m PyInstaller --version` | 输出版本号 |
| 1.4 | Inno Setup | 检查 `C:\Program Files (x86)\Inno Setup 6\ISCC.exe` | 存在则安装包可打；不存在则只验证 EXE 产物 |
| 1.5 | 端口占用 | `netstat -ano \| findstr :5000` | 记录是否有运行实例（冒烟时避开） |

## 2. 执行步骤（全部命令从仓库根 `PersonLLMWiki/` 执行）

### 2.1 快速回归测试
```bash
python -m pytest tests/desktop tests/chat/test_tool_map.py -q
```
- **预期**：全部通过。
- 已知预存失败（非本次引入，记录即可不阻断）：`tests/chat/test_thinking_stages.py`、`tests/chat/test_agent_expert.py`（引用了不存在的 `common.agent._get_active_llm`）、`tests/mcp/test_integration_workbuddy.py`（陈旧 ZSSNote 品牌断言）。

### 2.2 构建桌面包
```bash
python packaging/build_desktop.py <VERSION>
```
- **预期**：命令以退出码 0 结束；`release/` 下生成产物。
- 若失败：读 `packaging/build/desktop/warn-desktop.txt`（missing modules 清单）与 `release/` 下日志，诊断后报告。

### 2.3 产物校验（机器可判定的硬指标）
| 产物 | 检查 | 预期 |
|---|---|---|
| `release/dist/PersonLLMWiki/PersonLLMWiki.exe` | 存在、大小 | > 30 MB，时间戳为本次构建 |
| `release/dist/PersonLLMWiki/_internal/` | 目录 | 存在且非空 |
| `release/dist/PersonLLMWiki/seed/` | 目录 | 存在（播种数据已复制） |
| `release/installer/PersonLLMWiki-Setup-<VERSION>.<build>.exe` | 存在、大小 | 非空（ISCC 可用时） |

### 2.4 HTTP 冒烟（GUI 无法点击，用 HTTP 验证；端口冲突时设 `PORT=<其他>` 再启动）
```bash
# 启动打包后的 exe（后台）
start "" "release\dist\PersonLLMWiki\PersonLLMWiki.exe"
# 等待 3-8 秒后：
curl.exe -s -o NUL -w "%{http_code}" http://127.0.0.1:5000/shell          # 预期 200
curl.exe -s -X POST http://127.0.0.1:5000/mcp -H "Content-Type: application/json" -d "{\"jsonrpc\":\"2.0\",\"method\":\"tools/list\",\"id\":1}"   # 预期 19 个工具
# 冒烟完成后终止该 exe 进程
taskkill /IM PersonLLMWiki.exe /F
```
- **注意**：若 5000 已被用户实例占用，用 `PORT` 环境变量启动临时实例并在冒烟后清理；**不得 kill 用户已在运行的实例**。

## 5. 边界与约束

1. **不改源码**——仅执行构建/校验/冒烟；发现疑似代码问题只报告，不修改；
2. **不干扰用户环境**——不 kill 用户运行的 :5000 实例；冒烟用临时实例；
3. **GUI 无法点击**——交互式验证（安装向导、窗口操作）超出能力范围，需人工；
4. **安装包真机验证**——Setup.exe 安装后能否运行需人工实测，工具只验证产物存在性。
