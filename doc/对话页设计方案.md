# 对话页设计方案

> 最后更新：2026-08-12 | 模块路由 ~900 行 | 前端 JS ~2200 行 | CSS ~2300 行

---

## 1. 架构总览

```
chat.html (SSR)  ───── SSE ────→  routes.py (Flask Blueprint)
    │                                  │
    ├─ 三栏布局                        ├─ /api/chat/sessions          会话 CRUD
    ├─ 欢迎页（新建对话模式）            ├─ /api/chat/sessions/{id}/stream  SSE 流式对话
    ├─ 阶段节点式思考过程组件            ├─ /api/chat/sessions/{id}/regenerate  SSE 重新生成
    ├─ SSE 流式渲染                    ├─ /api/chat/upload            文件上传
    ├─ 附件上传 + 知识库浏览            ├─ /api/chat/preview-doc       知识库文档预览
    └─ 导出文件胶囊（预览 + 下载）       ├─ /api/chat/preview-attachment  附件预览
                                       ├─ /api/chat/file-exports/preview  导出文件预览
                                       ├─ /api/chat/file-exports/download 导出文件下载
                                       └─ /api/chat/kb-tree           知识库目录树
```

**新建对话模式**：首次进入对话页（无历史会话）时，中栏显示欢迎页（问候语）+ 输入框，无需手动点"新建对话"。用户直接输入消息 → `sendMsg()` 检测 `sid` 为空 → 自动 `createNewSession()` → 发送消息。

**后端核心**：`_generate_agent_sse()` 共享生成器函数（~170 行），统一封装 Agent SSE 流式协议（阶段事件 + 流式输出 + 持久化），`stream_message` 和 `regenerate_response` 两个路由均委托调用。

## 3. 左栏：会话管理

### 3.1 会话列表
- `GET /api/chat/sessions` 获取列表，按创建时间倒序
- 当前选中项高亮（`.active`）
- 空态显示 "暂无历史对话" 提示

### 3.2 新建会话
- `POST /api/chat/sessions` 创建，后端自动生成标题 "新对话"
- 前端 `createNewSession(cb)` → 更新 `localStorage.chat_sid` → `showChat()`

### 3.3 重命名
- 双击标题进入编辑态（`startRenameSession`）
- 单双击通过 350ms 定时器区分（单击=切换会话，双击=编辑标题）
- `PUT /api/chat/sessions/{id}` 提交新名称

### 3.4 删除
- 点击 × 按钮 → `customConfirm` 确认 → `DELETE /api/chat/sessions/{id}`
- 删除当前会话时自动切回欢迎页（`hideChat()`，输入框仍显示）

### 3.5 切换会话
- `selectSession(id)`：加载消息 + 关闭预览面板 + 处理流状态恢复

### 3.6 新建对话模式（v2）

对话页不再在欢迎页显示快捷操作按钮（总结文章/解释概念等），改为**直接输入即创建**的流程：

```
initChat()
  ├─ 无 savedSid → hideChat()（欢迎页 + 输入框）
  │     └─ 用户输入 → sendMsg()
  │           └─ sid 为空 → createNewSession(cb)
  │                 ├─ POST /api/chat/sessions 创建会话
  │                 ├─ showChat() 切换到对话视图
  │                 └─ cb = sendMsg() 自动重发
  └─ 有 savedSid → showChat() → loadMsgs(sid)
```

- `hideChat()` 不再隐藏输入框，确保欢迎态和对话态输入框均可用
- 已删除 `startWith()` 函数（快捷操作按钮已移除）

## 4. 中栏：对话核心区

### 4.1 消息渲染

使用共享 Markdown 渲染模块 `Md`（`static/js/utils/md.js`），后端 `markdown_service.py` 统一渲染：

- `Md.render(text)` → 异步返回 HTML（带 LRU 缓存 80 条）
- `Md.renderInto(text, container, {onDone})` → 渲染到指定 DOM 容器
- 后端调用 `/api/article/preview` 接口，由 `markdown_service.py` 处理（Python markdown 库 + 后处理）
- 支持：标题、粗斜体、代码块、引用、列表、链接/图片、表格、任务列表、Wiki 链接 `[[title]]`、来源标注 `^[source]`

**三类胶囊**：

| 类型 | CSS 类 | 颜色 | 触发 | 点击行为 |
|------|--------|------|------|---------|
| 知识库路径胶囊 | `.doc-file-pill` | 蓝色 | AI 回答中 `需求/xxx.md` 格式路径 | `previewDoc(path)` 预览知识库文档 |
| 用户附件胶囊 | `.chat-attach-pill` | 紫色 | 用户上传文件后渲染 | `previewAttachment(savedName, filename)` 预览附件 |
| 导出文件胶囊 | `.chat-export-pill` | 绿色 | Agent `create_document` 工具产出 | `previewExportedFile(filename)` 预览 + 下载 |

### 4.2 用户消息操作栏
- **复制**：`makeCopyBtn(content)` → Clipboard API
- **修改**：`editUserBubble()` → 气泡内 textarea → 保存后重新生成回答
- **三点菜单** → 删除问答对（`deleteMsgPair`，含高亮确认动画）

### 4.3 助手消息操作栏
- **复制**：同上
- **重新生成**：`regenerateFromAssistant()` → 删除旧回答 → 发起新 SSE 流

### 4.4 连续思考流（Continuous Thinking Stream）

> **v4 重新设计**：用手风琴→连续流。所有思考文字流成一段完整文本，不分步骤，像真人在打字思考一样逐字展现。完成后整个思考区收拢为可折叠摘要。

**设计理念**：
- 一气呵成——像真人在写思考过程，不分段不打断
- 打字机效果——逐字出现，有鲜活感，1 字符/50ms
- 完成后收拢——默认折叠为一行摘要，不占视觉空间
- 事后可复查——历史消息中点击可展开查看完整思考过程

**实时展示（打字机模式）**：

```
┌─ thinking-stream ────────────────────────────┐
│  ┌ 思考中... ⏳ ─────────────────────────── ┐ │
│  │                                          │ │
│  │  我先搜一下知识库，看有没有记录过MCU选型   │ │  ← 逐字追加
│  │  的经验……找到了3个相关概念，不过信息有    │ │
│  │  点旧了，再联网查查最新的芯片资料……       │ │
│  │  信息够了，整理一下思路……                 │ │
│  │                                     |     │ │  ← 闪烁光标
│  └──────────────────────────────────────────┘ │
│  ─ ─ ─ thinking-answer-divider ─ ─ ─         │
│  ┌─ 最终回答区 ────────────────────────────┐ │
│  │  Markdown 流式渲染                        │ │
│  └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

**完成后（历史消息，折叠态）**：

```
┌─ 思考过程（搜了知识库、查了网络）  [展开 ▼] ─┐  ← 一行摘要，点击展开
│  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─      │
│  最终回答……                                   │
└──────────────────────────────────────────────┘
```

**DOM 结构**：

```html
<div class="thinking-stream">
  <div class="thinking-header">
    <span class="thinking-dot"></span>          <!-- 加载中=旋转点 / 完成=✓ -->
    <span class="thinking-label">思考中...</span> <!-- 完成后变摘要 -->
    <button class="thinking-toggle">展开</button> <!-- 完成后显示，控制折叠 -->
  </div>
  <div class="thinking-body">                  <!-- 可折叠 -->
    <div class="thinking-text typing"></div>   <!-- 思考文字，逐字追加 -->
    <button class="thinking-skip-btn">跳过思考</button>
  </div>
  <div class="thinking-answer-divider">回答</div>
</div>
```

**交互行为**：
- 流式进行中：思考文字逐字追加到 `.thinking-text`，光标闪烁
- "跳过思考" 按钮 → 折叠 `.thinking-body`，直接显示回答
- 完成瞬间：`.thinking-dot` 旋转点 → ✓，`.thinking-label` 变为摘要
- 完成后：`.thinking-body` 默认折叠，点击 `.thinking-header` 展开/折叠
- 历史消息：全部默认折叠，点击 header 展开查看完整思考过程

**动画**：
- 打字机光标：`cursor-blink` 0.8s step-end 闪烁
- 思考区折叠/展开：`max-height` 过渡 250ms
- `prefers-reduced-motion` 时禁用过渡

### 4.5 SSE 流式协议

```
用户输入 → sendMsg() → POST /api/chat/sessions/{id}/stream
  │
  ├─ _startStreamFetch()  公共 fetch 封装
  │     │
  │     ├─ response.body.getReader()  逐块读取
  │     ├─ _makeProcessChunk()        解析 SSE data: 行
  │     │     ├─ data.stage_start  → _handleStageStart()  新增阶段节点
  │     │     ├─ data.stage_end    → _handleStageEnd()    标记完成
  │     │     ├─ data.thinking_done → _finishThinking()   折叠思考区
  │     │     ├─ data.chunk        → 追加 streamContent → _updateStreamDisplay()
  │     │     ├─ data.heartbeat    → 忽略（保活心跳）
  │     │     └─ data.done         → 结束流，刷新消息列表
  │     └─ _streamCatch()           错误处理（AbortError / 网络错误）
  │
  └─ AbortController  用户可随时停止生成
```

**SSE 事件序列**：

```
stage_start (stage_1: 分析问题)
  → stage_start (stage_2: 创建文档)  ← Agent tool_start
  → stage_end (stage_2: completed)   ← Agent tool_result
  → stage_start (stage_3: 写入内容)
  → stage_end (stage_3: completed)
  → ...（更多工具调用轮次）
  → thinking_done                     ← 思考过程结束
  → chunk × N                         ← 逐块流式输出回答
  → done {thinking, exported_files}   ← 最终事件
```

**流状态管理**：`window._streamState` 对象持有当前流的所有上下文：
- `active/done` — 生命周期标记
- `streamContent` — 累积的回答内容
- `thinking.stages[]` — 阶段数据数组
- `thinking.currentStageId` — 当前执行中的阶段 ID
- `thinking.*` DOM 引用 — process/detail/answer 各区 DOM
- `abortController` — 中止控制

**页面切换恢复**：`resumeStream()` 检测 `_streamState` 残留，设 `st.active=false` 暂停旧回调，重建 DOM 后恢复流式更新。

```

### 4.7 附件上传

```
用户选文件 → XHR POST /api/chat/upload
  │
  ├─ 服务端：secure_filename → {timestamp}_{safe_name}
  │          保存到 {ATTACHMENT_PATH}/chat_uploads/

## 5. 右栏：预览面板

三种预览类型共用 `_renderPreview(res, opts)` 渲染函数，统一处理面板展开、标题设置、内容渲染、下载按钮控制。Markdown 类型内容通过 `Md.renderInto()` 统一渲染，非 Markdown 类型（HTML/文本）直接设置 innerHTML 或 textContent。

### 5.1 文档预览（知识库）
- 点击 AI 回答中的文件路径胶囊 → `previewDoc(path)`
- `GET /api/chat/preview-doc?path=xxx` → 返回 `{type: 'markdown', content: '...'}` 
- 前端通过 `Md.renderInto()` 渲染 Markdown 为 HTML
- 无下载按钮

### 5.2 附件预览（上传文件）
- 点击用户消息中的附件胶囊 → `previewAttachment(savedName, filename)`
- `GET /api/chat/preview-attachment?file=savedName`
- 支持格式：
  - Office 文档（docx/xlsx/pptx）→ OfficeCLI 转 HTML
  - 文本文件（md/txt/json/py 等）→ Markdown 渲染
  - 其他 → 纯文本转义显示
- 无下载按钮

### 5.3 导出文件预览 + 下载
- 点击导出文件胶囊 → `previewExportedFile(filename)`
- `GET /api/chat/file-exports/preview?file=xxx` → OfficeCLI 转 HTML / Markdown 渲染
- **下载按钮可见**：点击 `GET /api/chat/file-exports/download?file=xxx` 触发浏览器下载
- 导出文件存储在 `{ATTACHMENT_PATH}/file_exports/` 目录

### 5.4 面板控制
- `toggleRightPanel()`：切换折叠/展开
- `resetRightPanel()`：清空内容，恢复折叠（切换会话时调用）
- 折叠时中栏自动占满

## 6. 关键数据流

### 6.1 发送消息全链路

```
用户输入文字 + 附件
  │
  ├─ 1. addBubble('user', displayText)  先渲染用户气泡（含附件胶囊）
  │      displayText = "内容\n\n[附件: a.docx#saved_a, b.pdf#saved_b]"
  │
  ├─ 2. POST /api/chat/sessions/{id}/stream
  │      body: { content, display_text, attachments, mode }
  │
  ├─ 3. 后端 _generate_agent_sse()：
  │      ├─ 发送 stage_start（分析问题）
  │      ├─ 后台线程执行 agent_chat（MCP 工具调用循环）
  │      ├─ 每轮工具调用 → stage_start + stage_end
  │      ├─ 发送 thinking_done
  │      ├─ 逐 chunk 流式输出回答
  │      ├─ 持久化 thinking_json（stages + exported_files）
  │      └─ 自动生成标题（仅 stream_message）
  │
  └─ 4. 前端：createStreamBubble() → _startStreamFetch() → 逐块渲染
               完成 → loadMsgs(sid) 重载历史（覆盖流式临时 DOM）
```

### 6.2 消息编辑 + 重新生成

```
用户点击"修改" → editUserBubble(bubbleEl, msgId, row, content)
  │
  ├─ textarea 替换气泡内容（剥离 [附件: ...] 后缀）
  ├─ 确认 → regenerateResponse(msgId, newContent, row, bubbleEl, fallbackHTML)
  │     │
  │     ├─ POST /api/chat/sessions/{id}/regenerate {message_id, content, mode}
  │     ├─ 后端：更新用户消息 → 删除旧回复 → _generate_agent_sse()（无标题生成）
  │     ├─ createStreamBubble(userRow) 创建新流气泡
  │     └─ _startStreamFetch → SSE 重新生成
  │
  └─ 取消 → 恢复原始 bubbleEl.innerHTML
```

## 7. thinking_json 持久化（v4）

Agent 思考过程通过 `thinking_json` 字段持久化，存储完整思考文字：

```json
{
  "thinking_text": "我先搜一下知识库...找到了3个概念...联网查查...",
  "exported_files": [
    {"filename": "xxx.docx", "path": "/full/path/to/xxx.docx"}
  ]
}
```

- **写入**：`_generate_agent_sse()` 结束时拼接所有 thinking_text → `json.dumps()` 存入
- **前端历史消费**：`loadMsgs()` 检测 `m.thinking_json.thinking_text` → 渲染可折叠思考区（默认折叠）
- **交互**：点击 header → 展开/折叠完整思考文字

## 13. Agent 端改动（思考文字生成）

### 13.1 System Prompt 修改

在 `common/agent.py` 的 system prompt 中新增指令：

```
在每次调用工具之前，用一句简短的口语化中文说明你在做什么、为什么这么做。
像自言自语一样自然。不要用列表、不要用 markdown 格式，就是一句自然的句子。

示例：
- "我先搜一下知识库，看有没有记录过电源芯片选型的经验"
- "知识库里的信息有点旧，联网查查最新的规格参数"

你的这句思考文字必须放在 function_call 之前，作为普通文本先输出。
```

Mermaid 图表语法规范通过 `_get_mermaid_prompt()` 函数注入，规则源文件为 `seed/skills/mermaid/SKILL.md`。每次启动时通过种子智能同步（`_seed_smart_sync`）更新到运行时目录，Agent 启动时自动加载。

### 13.2 SSE 新增 thinking_start / thinking_stream 事件

在 `_generate_agent_sse()` 中：

```
Agent 循环每轮:
  1. LLM 返回 text content（思考文字）
     → yield SSE: thinking_stream {stage_id, token}
  2. LLM 返回 function_call
     → yield SSE: stage_start {stage_id, stage_name, tool_name, tool_arguments}
  3. 执行工具调用
  4. 收集结果
     → yield SSE: stage_end {stage_id, status, duration_ms, result_summary}
```

**关键点**：
- `thinking_stream` 事件在 `stage_start` **之前**发送（LLM 先输出思考文字，再输出 function_call）
- 思考文字不进最终回答，只作为思考过程展示
- 如果模型不支持先文本后 function_call 的模式（如某些模型 function_call 模式不输出文本），则退化为仅显示 stage_name

### 13.3 阶段数据结构变更

`stages` 数组 → `steps` 数组，每项新增 `thinking_text` 字段：

```python
step = {
    "step_index": i,
    "stage_name": "搜索知识库",
    "tool_name": "search_kb",
    "tool_arguments": {"query": "..."},
    "thinking_text": "我先搜一下知识库...",
    "status": "completed",
    "duration_ms": 420,
    "result_summary": "找到 3 条结果"
}
```

### 13.4 回退兼容

旧版使用 `stages` 格式的历史消息仍可正常显示：检测 `thinking_json.stages`（旧）vs `thinking_json.steps`（新），前端兼容两种格式，旧格式用 stage_name 作为折叠行文字。
